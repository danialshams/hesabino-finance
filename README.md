# حسابینو — Hesabino Finance

**حسابینو** یک پروژه مستقل مدیریت مالی و حسابداری دوبل با Next.js App Router، PostgreSQL و Prisma است. رابط کاربری فارسی، راست‌چین و واکنش‌گراست. برنامه به هیچ حساب Lovable یا وابستگی اختصاصی Vercel متکی نیست. دیتابیس برای انتقال به هاست اختصاصی قابل جابه‌جایی است.

> **وضعیت:** نسخه توسعه‌ای و هنوز **آماده استفاده عملیاتی با داده مالی واقعی نیست**. کد منطق مالی و رابط اولیه ایجاد شده و تست‌های واحد بخش مبلغ/تراز انجام شده است. در محیط ساخت این پروژه دسترسی npm/PostgreSQL وجود نداشت و بنابراین نصب وابستگی‌ها، بیلد کامل، اجرای migrations و تست end-to-end/امنیت روی پایگاه داده واقعی **هنوز تأیید نشده‌اند**. این محدودیت را با عنوان «پیاده‌سازی کامل» اشتباه نگیرید.

## نیازمندی‌ها

- Node.js 22 یا بالاتر
- PostgreSQL 16 یا بالاتر (می‌تواند با Docker باشد)
- npm

## اجرای محلی

```bash
cp .env.example .env
# برای دیتابیس محلی:
docker compose up -d db
npm install
npm run db:init
npm run dev
```

به `http://localhost:3000` مراجعه کنید و یک حساب بسازید. برای اولین کاربر، شرکت و سرفصل‌های پیش‌فرض و یک دوره سال جاری میلادی ایجاد می‌شود. **این داده‌ها نمونه تراکنش مالی نیستند**؛ ارقام اولیه واقعی نیستند و تا زمان ثبت سند صفر خواهند بود. تاریخ‌های فرم در حال حاضر به فرمت میلادی ISO وارد می‌شوند، ولی نمایش تاریخ‌ها بر اساس تقویم جلالی است. در صورت نیاز به سال مالی شمسی، دوره مالی مورد نظر باید بعداً توسط مدیر سازمان و با تاریخ‌های میلادی متناظر تعریف شود.

### راه‌اندازی روی هاست اختصاصی

1. یک دیتابیس PostgreSQL و کاربر محدود فقط برای برنامه بسازید.
2. فایل `.env` تولید کنید و `DATABASE_URL` را روی PostgreSQL جدید قرار دهید. فایل `.env` را **در Git ثبت نکنید**.
3. `npm install && npm run db:init && npm run build && npm run start` را اجرا کنید.
4. در تولید واقعی اتصال TLS به دیتابیس، سیاست پشتیبان‌گیری، پایش، محدودسازی نرخ درخواست، محیط TLS/HTTPS و مدیریت secrets را فعال کنید.
5. اگر اطلاعات قبلاً در Vercel بوده، از PostgreSQL منبع با ابزارهای استاندارد `pg_dump` نسخه پشتیبان بگیرید و با `pg_restore` به دیتابیس جدید انتقال دهید. پس از بازیابی، تنظیمات اتصال را عوض کرده و عملکرد گزارش‌ها را اعتبارسنجی کنید.

برای Docker، ابتدا `docker compose up -d db` را اجرا کنید و برنامه را طبق Dockerfile با آدرس داخلی `db` اجرا کنید (نمونه compose فعلاً برای **دیتابیس محلی** است).

## بخش‌های موجود در کد

- حساب کاربری: ثبت‌نام، ورود ایمیل/رمز، نشست‌های هش‌شده در PostgreSQL، خروج، سطح دسترسی مالک/مدیر/حسابدار/مدیرمالی/مشاهده‌گر؛ افزودن عضو موجود به شرکت با ایمیل.
- سازمان‌ها و شعب، تفکیک اطلاعات در queryهای API، سرفصل حساب‌ها، دوره مالی و قفل بستن دوره.
- اسناد دوبل: پیش‌نویس و ثبت قطعی، سند برگشت دستی، تراز بودن، کنترل تاریخ دوره، عدم ویرایش سند ثبت‌شده، Audit.
- طرف‌حساب‌ها، فاکتور خرید و فروش با اقلام، تخفیف و مالیات ریالی، صدور فاکتور با تولید سند، چاپ و ذخیره PDF با مرورگر.
- بانک/صندوق، دریافت و پرداخت و انتقال، تسویه فاکتور و ثبت اسناد خودکار، ثبت اقساط و مانده پرداخت.
- بودجه‌ها، مراکز هزینه، پروژه‌ها و الگوهای تکرارشونده قابل اجرای دستی در سررسید.
- گزارش‌های تراز آزمایشی، دفتر کل، سود و زیان، ترازنامه، جریان نقدی، سررسید بدهی/مطالبات، کنترل بودجه، سودآوری پروژه و پیش‌بینی مبتنی بر سررسید فاکتورها، خروجی CSV و چاپ.
- داشبورد شاخص‌ها، نمودار درآمد/هزینه و هشدارهای مشتق‌شده از اطلاعات مالی.

### تضمین‌های طراحی‌شده

- همه مبلغ‌ها در PostgreSQL به‌صورت **BIGINT ریال** هستند، انتقال داده JSON به‌صورت رشته انجام می‌شود و همه محاسبات حسابداری با BigInt صورت می‌گیرند.
- در تراکنش‌های Prisma از سطح ایزوله‌سازی `Serializable` برای عملیات کلیدی استفاده شده است.
- `prisma/guards.sql` از حذف/تغییر اسناد قطعی، تغییر خطوط آن‌ها، اسناد نامتوازن، خط مستقیم بین شرکت‌ها در خطوط سند و تغییر سوابق حسابرسی جلوگیری می‌کند. اجرای این فایل **پس از ساخت schema الزامی است**.
- `requireMember` در API باید روی تمام درخواست‌های مربوط به هر شرکت اعمال شود. این کنترل‌ها جایگزین ارزیابی امنیتی مستقل نیستند.
- **اظهار انطباق با الزامات مالیاتی ایران نمی‌کنیم.** اتصال سامانه مؤدیان، چک، حقوق‌ودستمزد و صورت‌حساب رسمی مالیاتی نیازمند کار تخصصی جداگانه است.

### موارد باقیمانده برای آماده‌سازی نسخه واقعی

- اجرای واقعی migrations و SQL guard روی PostgreSQL 16 و تست تراکنش‌های همزمان.
- تست یکپارچه فاکتور/تسویه/سند برگشت/گزارش، رفع خطاهای تایپی یا بیلد پس از نصب وابستگی‌ها.
- نوشتن integration/e2e tests، تست نفوذ و بررسی مستقل حسابدار حرفه‌ای.
- RLS سطح دیتابیس یا معماری اتصال با نقش محدود و context tenant؛ حفاظت فعلی فقط در سرویس/route و چند trigger پیاده شده است.
- مدیریت خطای پیشرفته و retry تراکنش‌های `Serializable`، محدودسازی نرخ ورود و CAPTCHA در صورت حمله، بازیابی رمز، 2FA و تایید ایمیل.
- اتوماتیک‌سازی اجرای recurring rules (فعلاً اجرای سررسید دستی است)، پیامک/ایمیل یادآورها، دریافت CSV صورت‌حساب بانکی و انتخابگر بصری برای مغایرت‌گیری، پیش‌بینی دقیق‌تر نقدینگی.
- ارائه صادرات کامل داده‌ها، پیوست فایل با S3-compatible، نسخه پشتیبان خودکار، دسترسی شعب، بستن سال مالی با سند اختتامیه و افتتاحیه (فعلاً فقط بستن دوره).
- تطبیق رسمی الزامات حقوقی/مالیاتی کسب‌وکار هدف.

## ساختار پروژه

- `app/` صفحات Next.js و API routes
- `components/` رابط کاربری
- `lib/ledger.ts` منطق حسابداری دوبل و posting
- `lib/reports.ts` منطق محاسبه گزارش‌ها
- `lib/auth.ts` نشست و سطح دسترسی
- `prisma/schema.prisma` مدل پایگاه داده
- `prisma/guards.sql` کنترل‌های سختگیرانه در سطح PostgreSQL
- `tests/` تست‌های واحد بدون اتصال به دیتابیس

### نکته انتشار

برای اتصال به GitHub و Vercel ابتدا این پوشه را در **مخزن مستقل جدید** قرار دهید. روی Vercel فریمورک Next.js، متغیر `DATABASE_URL` و `build` معمول Next.js تنظیم شود. در زمان build از `prisma generate` استفاده شده است. برنامه نباید هیچ migration را به‌صورت خودکار در هر request اجرا کند.
